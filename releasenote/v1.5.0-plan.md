## 変更の目的・背景

GitHub Issue #11（`tasksで複数コマンドをリスト定義できるようにする`）への対応。
現行（v1.4.0）の `devctl` では、プロジェクトの `tasks` 定義（`TaskItem`）が単一の `command` 文字列のみを保持する構造となっており、初期セットアップ（`composer install` → `migrate` → `db:seed` 等）のように複数のコマンドを順番にまとめて実行したい場合に扱いづらい課題があった。
本改修では、既存の `description` + `command`（単一文字列）形式との後方互換性を完全に維持しつつ、タスク名直下へのコマンド配列定義および `commands`（または `command` 配列）による複数コマンドのリスト定義をサポートし、定義順での順次実行と失敗時の即時停止（Fail-Fast）を実現する。

## 要求仕様一覧

- [x] 要求項目1: `internal/config/config.go` の `TaskItem` 拡張および複数 YAML 記法のサポート
  - `TaskItem` に `Commands []string` フィールドおよび実行コマンド一覧を返す `GetCommands() []string` メソッドを追加する。
  - `TaskItem.UnmarshalYAML(value *yaml.Node) error` を実装し、以下の YAML 定義フォーマットをすべてパース可能にする：
    1. 直リスト形式: `tasks.<name>: ["command-a", "command-b"]`
    2. マップ + 複数コマンド形式: `tasks.<name>: { description: "...", commands: ["command-a", "command-b"] }`（および `command` キーに配列を指定した場合も許容）
    3. 既存のマップ + 単一コマンド形式: `tasks.<name>: { description: "...", command: "command-a" }`（および単一スカラー文字列 `tasks.<name>: "command-a"`）
  - 各コマンドの引数や環境変数はシェル実行文字列（`sh -c`）内でインライン指定できる設計を維持する。
- [x] 要求項目2: `internal/docker/compose.go` および `internal/cmd/project.go` における複数コマンド順次実行と Fail-Fast 制御の実装
  - `ComposeClient` に複数コマンドを定義順に実行する `RunShellTasks(workDir string, commands []string) error` を追加する（既存の `RunShellTask` との互換性も維持）。
  - 複数コマンド実行時はステップ進捗（例: `[1/2] カスタムタスクを実行中: ...`）を表示し、ランナー層（`c.runner.RunShell`）を経由して `--dry-run` に対応する。
  - 実行中にいずれかのコマンドが失敗（非ゼロ終了）した場合は、後続のコマンドを実行せず即座に中断（Fail-Fast）し、失敗したステップとエラー内容を呼び出し元へ返却する。
  - `projectRunCmd` において、`task.GetCommands()` を用いて実行し、コマンドが空の場合は適切なエラーメッセージを返す。
- [x] 要求項目3: 単体テスト・自動検証の拡充
  - `internal/config/config_test.go` に、直リスト形式・`commands` リスト形式・既存 `command` 形式の YAML パース検証テストを追加する。
  - `internal/docker/compose_test.go` および `internal/cmd/project_test.go` に、複数コマンドの順次実行（Dry-Run 含む）および途中コマンド失敗時に後続コマンドが実行されず即時停止（Fail-Fast）することの単体テストを追加する。
  - `go vet ./...` および `go test ./...` を実行し、静的解析警告・テスト失敗が 0 件であることを確認する。
- [x] 要求項目4: ドキュメントおよび設定例の更新（`documentation.md` 準拠）
  - `README.md`、`configs/config.example.yaml`、および `internal/config/template.go` に、複数コマンドをリスト定義するタスクの記述例と仕様（定義順実行・失敗時の即時停止）を追記する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（既存の `tasks.<name>.command` による単一コマンド定義および CLI 引数の互換性を完全に維持すること）。
- **ランナー層の経由**: 外部コマンドの実行は必ず `internal/docker/runner.go`（`RunShell`）を経由し、`--dry-run` 時には実行予定の全コマンドを定義順に出力すること。
- **外部パッケージの追加**: 原則不可（標準ライブラリおよび既存の Cobra / `gopkg.in/yaml.v3` パッケージの範囲で実装すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守し、`CGO_ENABLED=0` による静的リンク性を維持すること。
