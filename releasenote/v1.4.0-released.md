## 変更概要

- GitHub Issue #13（`project / core にイメージ取得用の pull コマンドを追加する`）への対応。
- コンテナを起動・再作成せずに、設定済みの Compose 定義からコンテナイメージのみを明示的に取得する `devctl project pull [project-name] [services...]`（短縮エイリアス: `devctl pull`）および `devctl core pull [services...]` コマンドを新設。
- 各 `project` / `core` の設定（`workdir`, `compose_files`, `env_file`, および `-f` / `--file` フラグ）を反映し、`--dry-run` による実行予定コマンドのプレビューおよび Compose 失敗時の終了ステータス伝播に対応。

## 破壊的変更（互換性への影響）

- なし（既存の `config.yaml` のスキーマや `devctl build --pull` を含む既存サブコマンド・フラグとの互換性を完全に維持しています）。

## 変更詳細

### 1. Compose クライアントへの `Pull` メソッド追加 (`internal/docker/compose.go`)

- `ComposeClient.Pull(opts ComposeOptions) error` を追加しました。
- `buildBaseArgs(opts)` を用いて Compose ファイル（自動 override マージまたは `-f` 指定ファイル）および `--env-file` を構築し、`runner.RunCommand` 経由で `docker compose ... pull [services...]` を実行します。
- 認証情報は Docker 側の既存の認証設定（環境変数・`~/.docker/config.json`）をそのまま引き継ぎ、エラー発生時は呼び出し元へ確実にラップして伝播します。

### 2. プロジェクト用 `pull` コマンドと短縮エイリアスの追加 (`internal/cmd/project.go`)

- `devctl project pull [project-name] [services...]` およびトップレベル短縮エイリアス `devctl pull [project-name] [services...]` を追加しました。
- `resolveTargetProject` により、プロジェクト名指定とカレントディレクトリからの自動検出の両方に対応します。
- `-f` / `--file` フラグによる追加・上書き Compose ファイル指定をサポートし、コンテナの起動や依存サービスの自動起動（`prepareDependencies`）を行わずにイメージ取得のみを実行します。

```bash
# プロジェクトの全サービスイメージを取得
devctl project pull sample
devctl pull sample

# 特定サービスおよび追加 Compose ファイル指定で取得
devctl pull sample app db -f compose.prod.yml
```

### 3. 共通基盤（Core）用 `pull` コマンドの追加 (`internal/cmd/core.go`)

- `devctl core pull [services...]` を追加しました。
- `core.workdir` の設定検証・存在確認（非 dry-run 時）を行い、`core.compose_files` および `core.env_file` に基づいて全サービスまたは指定サービスのイメージを取得します。

```bash
# 共通基盤の全サービスイメージを取得
devctl core pull

# 特定サービスのイメージのみを取得
devctl core pull traefik dbgate
```

### 4. 単体テストおよびドキュメントの更新 (`internal/docker/compose_test.go`, `internal/cmd/project_test.go`, `README.md`, `configs/config.example.yaml`)

- `TestComposeClient_Pull`（通常実行、サービス・`-f` 指定時、およびコマンド失敗時のエラー伝播検証）を追加しました。
- `TestPullCmd_FlagsAndRegistration` および `TestPullCmd_Execution`（`project pull`, `pull`, `core pull` の登録・フラグ・Dry-Run 実行・異常系エラー検証）を追加しました。
- `README.md` および `configs/config.example.yaml` に使用例と `devctl pull` / `devctl build --pull` の使い分けガイドを追記しました。
