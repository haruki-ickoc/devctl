## 変更の目的・背景

GitHub Issue #14（`project / core に Docker volume の backup / restore コマンドを追加する`）への対応。
従来のプロジェクト固有スクリプトは Docker デーモン上の全 Volume を対象とし、バックアップ前に全コンテナを強制削除するため、複数プロジェクトを共存させる開発環境では影響範囲が広く安全に利用できない課題があった。
本改修では、`devctl project backup` / `devctl project restore` および `devctl core backup` / `devctl core restore`（ならびに事前一時停止のための `devctl core stop` / `devctl core start`）を追加し、指定した `project` または `core` スコープ内の Named Volume のみをコンテナを削除せずに安全にアーカイブ退避・復元できるようにする。

## 要求仕様一覧

- [x] 要求項目1: スコープ限定 Volume 解決および稼働状態チェック機構の実装 (`internal/docker/volume.go` / `compose.go`)
  - 対象の `project` または `core` の Compose 定義（`-f` 指定および `BUILD_ENV` / 標準 override を含む）から、管理対象の論理 Volume 名と実 Docker Volume 名（`<compose-project>_<volume>` または明示 `name`）のマッピングを解決する機能を実装する。
  - 引数 `[volumes...]` が指定された場合は対象スコープ内の Volume のみに絞り込み、スコープ外の Volume 名が指定された場合はエラーとして拒否する（無関係な Docker Volume やコンテナには一切影響させない）。
  - コンテナの削除（`down` / `rm`）は一切行わない。データの整合性を担保するため、対象スコープに稼働中（`running`）のサービスが存在する状態、または対象 Volume をマウントして稼働中のコンテナが存在する状態では `backup` / `restore` の実行を拒否し、事前に `devctl project stop <project>`（または `devctl stop <project>` / `devctl core stop`）で一時停止するよう案内して非ゼロ終了ステータスを返す。
- [x] 要求項目2: Volume Backup 機能の実装 (`internal/docker/volume.go`)
  - デフォルトの保存先を `<対象WorkDir>/.devctl/backups/<project-or-core>-<YYYYMMDD-HHMMSS>.tar.gz` とし、`-o` / `--output` フラグによる任意ファイルパスの指定にも対応する。
  - 対象の実 Docker Volume が存在しない場合は明示的なエラーを表示して中断する。
  - ランナー層（`internal/docker/runner.go`）を経由して一時コンテナ（`alpine:latest`）を `docker run --rm` で実行し、対象 Volume を読み取り専用（`:ro`）で `/volumes/<論理Volume名>` にマウントした上で、単一の `.tar.gz` アーカイブとして退避する（`--dry-run` 完全対応）。
  - 実行した対象 Volume 一覧と出力先アーカイブファイルパスをターミナルに明示表示する。
- [x] 要求項目3: Volume Restore 機能・アーカイブ検証・事前確認プロンプトの実装 (`internal/docker/volume.go`)
  - 復元実行前に Go 標準ライブラリ（`compress/gzip`, `archive/tar`）を用いて指定アーカイブファイルの存在・形式・破損有無・収録されている論理 Volume 一覧を検証する（不正なアーカイブや対象 Volume が含まれない場合は実行前にエラー終了する）。
  - 上書き対象の Volume 一覧（論理名および実 Docker Volume 名）と復元元アーカイブパスを事前に表示し、対話プロンプト（`[y/N]`）で確認後に実行する（`-y` / `--yes` フラグ指定時はプロンプトをスキップ可能、非対話環境で `-y` 未指定時は安全のため拒否する）。
  - 復元対象の実 Docker Volume が未作成の場合は、Docker Compose 互換ラベル（`com.docker.compose.project`, `com.docker.compose.volume`）を付与して `docker volume create` で自動作成してから復元を行う。
  - ランナー層を経由した一時コンテナ実行により、対象 Volume 内の既存データをクリアした上で選択された Volume のデータを展開・復元する。
- [x] 要求項目4: CLI サブコマンド（`project backup/restore`, `core backup/restore`, `core start/stop`）の実装 (`internal/cmd/project.go`, `internal/cmd/core.go`)
  - 以下のサブコマンドを追加する（トップレベル短縮エイリアスは設けない）：
    - `devctl project backup [project-name] [volumes...] [-o/--output <path>] [-f/--file <compose-file>]`
    - `devctl project restore [project-name] <backup> [volumes...] [-y/--yes] [-f/--file <compose-file>]`
    - `devctl core backup [volumes...] [-o/--output <path>]`
    - `devctl core restore <backup> [volumes...] [-y/--yes]`
    - `devctl core stop [services...]` / `devctl core start [services...]`（Core 環境でもコンテナを削除せずに一時停止して backup / restore を行えるようにするため）
  - `project backup` / `project restore` では、プロジェクト名引数の指定およびカレントディレクトリからのプロジェクト自動検出の双方に対応する。
- [x] 要求項目5: 単体テスト・自動検証の拡充 (`internal/docker/volume_test.go`, `internal/cmd/project_test.go`)
  - スコープ外 Volume 指定時の拒否、稼働中コンテナ存在時の拒否、アーカイブ検証（正常系・破損アーカイブ・未収録 Volume 検出）、未作成 Volume の自動作成、確認プロンプト制御、および `--dry-run` でのコマンド構築を検証する単体テストを追加する。
  - `go vet ./...` および `go test ./...` を実行し、静的解析警告・テスト失敗が 0 件であることを確認する。
- [x] 要求項目6: ドキュメントおよび設定例の更新（`documentation.md` 準拠）
  - `README.md` および `configs/config.example.yaml` に、`project backup / restore`・`core backup / restore` の使用方法、事前 `stop` による安全な退避・復元フロー、デフォルト保存先（`<workdir>/.devctl/backups/`）、およびアーカイブ形式（トップレベル `<論理Volume名>/` 構造の `.tar.gz`）の仕様を追記する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（既存のサブコマンド体系や `config.yaml` の互換性を完全に維持すること）。
- **ランナー層の経由**: 外部コマンドの実行は必ず `internal/docker/runner.go` を経由し、`--dry-run` 時には実行予定コマンドを正確に出力すること。
- **外部パッケージの追加**: 原則不可（アーカイブ検証等も Go 標準ライブラリ `archive/tar`, `compress/gzip` の範囲で実装し、`CGO_ENABLED=0` による単一バイナリを維持すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守すること。
