## 変更概要

- Docker Compose の標準仕様に準拠し、プロジェクト作業ディレクトリ内に存在する override ファイル（`compose.override.yml`, `compose.override.yaml`, `docker-compose.override.yml`, `docker-compose.override.yaml`）を自動的に認識・マージする機能を実装しました。
- Dockerfile の開発用/本番用ステージ分離（マルチステージビルド）において、`compose.override.yml` で指定された `build.target: dev` やソースコードのバインドマウントが正しく適用されるようになりました。
- プロジェクト操作コマンド群（`up`, `down`, `restart`, `logs`, `ps`, `exec`）に `-f / --file` フラグを追加し、本番用設定（`compose.prod.yml` 等）を重ねて起動・停止する環境切り替えを devctl から直接行えるようにしました。
- 単体テストの追加・拡充および設定例・README ドキュメントの更新を行いました。

## 破壊的変更（互換性への影響）

- なし（既存の `config.yaml` 構文や override ファイルを持たない通常プロジェクトとの完全な後方互換性を維持しています）。

## 変更詳細

### 1. Docker Compose override ファイルの自動検出・マージ

- [internal/config/config.go](file:///home/skyou/workspace/devctl/internal/config/config.go):
  - `FindOverrideFile(workDir, baseFile string) string` を追加。作業ディレクトリ内のベース Compose ファイルに対応する override ファイル候補を自動探索します。
  - `detectComposeFiles` を拡充し、設定ファイルで `compose_files` が省略された場合でもベースファイルと override ファイルの両方を検出して返却します。
- [internal/docker/compose.go](file:///home/skyou/workspace/devctl/internal/docker/compose.go):
  - `buildBaseArgs` において、`ComposeFiles` に明示的な override ファイルが含まれていない場合、作業ディレクトリ内の override ファイルを自動的に `-f <override>` として付加します。
  - 既に override ファイルが含まれている場合の重複付加を防止するガードロジックを実装。

### 2. プロジェクト操作コマンドへの `--file` / `-f` フラグ追加

- [internal/cmd/project.go](file:///home/skyou/workspace/devctl/internal/cmd/project.go):
  - `projectUpCmd`, `topUpCmd`, `projectDownCmd`, `topDownCmd`, `projectRestartCmd`, `topRestartCmd`, `projectPsCmd`, `projectExecCmd` に `-f / --file` フラグを追加。
  - `projectLogsCmd`, `topLogsCmd` では既存の `--follow (-f)` との競合を回避するため短縮なしの `--file` フラグとして登録。
  - カスタム Compose ファイルが指定された場合（例: `devctl up sample -f compose.prod.yml`）、開発用 override ファイル（`*.override.*`）を自動的に除外し、ベースファイルに指定ファイルを重ねて適用します。

### 3. 単体テストの拡充

- [internal/config/config_test.go](file:///home/skyou/workspace/devctl/internal/config/config_test.go):
  - `TestDetectComposeFiles` に override ファイル自動検出のテストケースを追加。
  - `TestFindOverrideFile` を新規追加。
- [internal/docker/compose_test.go](file:///home/skyou/workspace/devctl/internal/docker/compose_test.go):
  - `TestBuildBaseArgs` を新規作成し、以下のシナリオを網羅的に検証:
    1. override が存在しない場合はベースファイルのみ渡されること
    2. override が存在する場合は自動で `-f` が付加されること
    3. すでに ComposeFiles に含まれる場合は二重追加されないこと
    4. CustomComposeFiles 指定時は開発用 override が除外されカスタムファイルが適用されること
    5. EnvFile 指定時に `--env-file` が正常に付加されること

### 4. 設定例およびドキュメントの更新

- [configs/config.example.yaml](file:///home/skyou/workspace/devctl/configs/config.example.yaml):
  - `sample` プロジェクト設定に Compose override 自動マージおよび `-f` による環境切り替えのベストプラクティスをコメント追記。
- [README.md](file:///home/skyou/workspace/devctl/README.md):
  - 「主な特徴」に Compose Override 自動マージ & 環境別切り替え (`-f`) を追加。
  - 「プロジェクト操作」セクションに `devctl up sample -f compose.prod.yml` の使用例と解説ノートを追記。
