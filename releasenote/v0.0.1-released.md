## 変更概要

複数プロジェクトの Docker Compose 環境および共通基盤（共通ネットワーク、リバースプロキシ、共通 DB 等）を統合管理する CLI ツール 「devctl」
の全体設計・設定ファイル仕様策定、およびベースとなる骨組みコードの実装が完了しました。

## 1. 推奨するディレクトリ構成

Go の標準レイアウト（Standard Go Project Layout）に準拠し、依存なしの単一バイナリ生成（CGO_ENABLED=0）やテスタビリティ、拡張性を確保した構成としています。

```text
  devctl/
  ├── cmd/
  │   └── devctl/
  │       └── main.go                  # エントリポイント
  ├── internal/
  │   ├── cmd/                         # Cobra コマンド群
  │   │   ├── root.go                  # ルートコマンド、グローバルフラグ (--config, --dry-run, --verbose)
  │   │   ├── core.go                  # devctl core (共通基盤の up, down, restart, logs, ps)
  │   │   ├── project.go               # devctl project / エイリアス (各プロジェクト操作・タスク実行)
  │   │   ├── network.go               # devctl network (共通ネットワークの確認・自動作成・削除)
  │   │   ├── ps.go                    # devctl ps (コア・全プロジェクト横断ステータス一覧)
  │   │   ├── config_cmd.go            # devctl config (設定初期化・確認・構文およびパス検証)
  │   │   └── version.go               # devctl version (バージョン情報表示)
  │   ├── config/                      # 設定ファイル管理
  │   │   ├── config.go                # 設定構造体、YAMLロード、チルダ/環境変数展開、PJ自動検出
  │   │   └── template.go              # デフォルト設定テンプレート
  │   ├── docker/                      # Docker & Compose 操作ラッパー
  │   │   ├── compose.go               # docker compose コマンドビルダー & 実行
  │   │   ├── network.go               # docker network の存在確認・自動作成・削除
  │   │   └── runner.go                # コマンド実行（DryRun対応・標準出力ストリーミング）
  │   └── ui/                          # ターミナル出力装飾
  │       └── output.go                # カラー出力・アイコン表示ユーティリティ
  ├── configs/
  │   └── config.example.yaml          # 設定ファイル仕様の実例サンプル
  ├── Makefile                         # ビルド・テスト・クロスコンパイル用
  ├── README.md                        # 利用ガイド・コマンドリファレンス
  ├── go.mod
  └── go.sum
```

## 2. 設定ファイル（config.yaml）のフォーマット仕様案

設定ファイルの配置場所は以下の優先順位で自動解決されます：

1. コマンドライン引数 --config <path> (または -c)
2. 環境変数 DEVCTL_CONFIG
3. カレントディレクトリの .devctl.yaml / devctl.yaml
4. ユーザーホーム: ~/.config/devctl/config.yaml

パス指定にはチルダ展開 (~/...) や環境変数展開 (${VAR}) が利用可能です。

config.example.yaml:

```yml
  version: "1"
```

## 全体デフォルト設定

  defaults:
    compose_cmd: "docker compose" # または "docker-compose"
    env_file: ".env"

### 共通 Docker ネットワーク定義

#### プロジェクトや Core の起動時に devctl が存在を確認し、なければ自動作成します

```yml
  network:
    name: "dev-network"
    driver: "bridge"
    attachable: true
```

### 共通インフラ基盤 (Core Services)

#### リバースプロキシ、ログ基盤、共通DB、Redis などの統合管理

```yml
  core:
    workdir: "~/workspace/core-infra"
    compose_files:
      - "docker-compose.yml"
    env_file: ".env"
    services:
      traefik:
        description: "Traefik Reverse Proxy & SSL termination"
      mailhog:
        description: "Local SMTP Testing Mail Server"
      mysql:
        description: "Shared MySQL Database Server"
      redis:
        description: "Shared Redis Cache Server"
```

### 管理対象の各プロジェクト定義

```yml
  projects:
    web-app:
      description: "Main Web Application (Next.js + Go)"
      workdir: "~/workspace/web-app"
      compose_files:
        - "docker-compose.yml"
        - "docker-compose.override.yml"
      env_file: ".env.local"
      # プロジェクト起動前に自動確保すべき依存関係
      depends_on:
        network: true
        core:
          - "mysql"
          - "redis"
      # 各リポジトリに散在していた Makefile の処理を吸収するカスタムタスク
      tasks:
        migrate:
          description: "Run DB migrations"
          command: "docker compose exec app go run ./cmd/migrate"
        seed:
          description: "Seed database fixtures"
          command: "docker compose exec app go run ./cmd/seed"
        bash:
          description: "Open shell inside app container"
          command: "docker compose exec app sh"

    billing-service:
      description: "Billing Microservice API"
      workdir: "~/workspace/billing-service"
      compose_files:
        - "docker-compose.yml"
      depends_on:
        network: true
        core:
          - "mysql"
      tasks:
        test:
          description: "Run containerized tests"
          command: "docker compose exec billing go test ./..."
```

## 3. サブコマンド体系の定義

Docker Compose ライクかつ日常の開発フローでストレスのない操作体系を設計しました。

### ① 共通基盤 (Core Infrastructure)

```text
 コマンド                                                                              │ 説明
───────────────────────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────
 devctl core up [services...]                                                          │ 共通ネットワークを自動確認・作成した上で Core コンテナを起動 (-b で再ビルド)
 devctl core down                                                                      │ 共通基盤を停止 (-v でボリューム削除)
 devctl core restart                                                                   │ 共通基盤を再起動
 devctl core ps                                                                        │ 共通基盤の稼働コンテナ状況を表示
 devctl core logs [-f]                                                                 │ 共通基盤のログを表示
```

### ② プロジェクト操作 (Project Management)

任意のディレクトリから対象プロジェクトを操作できます。

```text
 コマンド                                                 │ 短縮エイリアス                                          │ 説明
──────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────
 devctl project list                                      │ devctl list, devctl ls                                  │ 登録済みプロジェクト一覧を表示
 devctl project up <name>                                 │ devctl up <name>                                        │ 依存する共通基盤・ネットワークを準備して起動
 devctl project down <name>                               │ devctl down <name>                                      │ プロジェクトコンテナを停止
 devctl project restart <name>                            │ devctl restart <name>                                   │ プロジェクトコンテナを再起動
 devctl project logs [-f] <name>                          │ devctl logs <name>                                      │ プロジェクトのログを表示
 devctl project ps <name>                                 │ -                                                       │ プロジェクトのコンテナ一覧を表示
 devctl project exec <name> <svc> <cmd>                   │ -                                                       │ コンテナ内で任意コマンドを実行
 devctl project run <name> <task>                         │ devctl run <name> <task>                                │ 定義済みカスタムタスク（旧 Makefile 処理）を実行
```

│ Tip
│ カレントディレクトリの自動判別機能:
│ カレントディレクトリが登録済みプロジェクト配下にある場合、<name> の指定を省略可能です。
│ 例: ~/workspace/web-app ディレクトリ内で単に devctl up や devctl run migrate と打つだけで動作します。

### ③ 全体ステータス・共通ネットワーク・設定管理

```text
 コマンド                                                                              │ 説明
───────────────────────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────
 devctl ps                                                                             │ 共通ネットワーク、Core、全プロジェクトの稼働状況を横断して一括表示
 devctl network check                                                                  │ 共通ネットワークの存在確認
 devctl network create                                                                 │ 共通ネットワークの手動作成
 devctl network rm                                                                     │ 共通ネットワークの削除
 devctl config init                                                                    │ ~/.config/devctl/config.yaml のひな形を自動生成
 devctl config path                                                                    │ 現在読み込まれている設定ファイルのパスを表示
 devctl config view                                                                    │ 読み込まれている設定内容を YAML 出力
 devctl config check                                                                   │ 構文および記載されたディレクトリ・compose ファイルの実在性を検証
 devctl version                                                                        │ バージョン・ビルド情報の表示

※ すべてのコマンドで --dry-run (-n) を指定して実行されるコマンドのプレビューが可能です。
```

## 4. 作成したコードと動作確認

### 実装ファイル一覧

- エントリポイント: main.go
- CLI コマンド群:
  - root.go
  - core.go
  - project.go
  - network.go
  - ps.go
  - config_cmd.go
  - version.go
- 設定管理: config.go, template.go
- Docker 実行層: compose.go, network.go, runner.go
- 出力装飾: output.go
- ビルド定義 & ドキュメント: Makefile, README.md

### ビルドとバイナリ仕様

make build により、静的リンクされた単一バイナリ（サイズ: 約 3.1MB）が bin/devctl に生成されます。

```bash
  $ ls -lh bin/devctl
  -rwxr-xr-x 1 skyou skyou 3.1M Sep 19 14:37 bin/devctl
  $ file bin/devctl
  bin/devctl: ELF 64-bit LSB executable, x86-64, statically linked, stripped
```

### 動作確認テストの実行例

- 設定ファイルの診断 (devctl config check):

```bash
  $ ./bin/devctl -c configs/config.example.yaml config check
  ✔ Configuration file syntax is valid: .../configs/config.example.yaml
  ==> Checking Shared Network Configuration:
  ℹ   Network Name: dev-network
  ℹ   Driver:       bridge
  ...
  ✔ Configuration check complete.
```

- プロジェクト起動シミュレーション (devctl up web-app --dry-run):

依存する共通ネットワークの自動作成 → Core の依存サービス (mysql) の起動 → プロジェクトの起動が自動順序でプレビューされます。

```bash
  $ ./bin/devctl -c configs/config.example.yaml -n up web-app
  ℹ Network 'dev-network' not found. Creating...
  [exec]: docker network create --driver bridge --attachable dev-network
  ✔ Network 'dev-network' created successfully.
  ℹ Ensuring core dependencies for web-app: [mysql redis]
  ==> Starting containers in ~/workspace/core-infra...
  [exec] (in ~/workspace/core-infra): docker compose -f docker-compose.yml up -d mysql redis
  ==> Starting containers in ~/workspace/web-app...
  [exec] (in ~/workspace/web-app): docker compose -f docker-compose.yml -f docker-compose.override.yml --env-file .env.local up -d
  ✔ Project 'web-app' started successfully.
```

- Makefile 代替タスクの実行 (devctl run web-app migrate --dry-run):

```bash
  $ ./bin/devctl -c configs/config.example.yaml -n run web-app migrate
  ℹ Running task 'migrate' in project 'web-app'...
  ==> Running custom task: docker compose exec app go run ./cmd/migrate
  [shell] (in ~/workspace/web-app): docker compose exec app go run ./cmd/migrate
```
