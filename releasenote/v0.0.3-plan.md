## 変更の目的・背景

開発チームへの展開や初期環境構築を円滑にするため、チーム内で準備された設定ファイル（`config.yaml`）を配布・インポートする運用に対応する。
これに伴い、`devctl config init` を拡張して以下の2つの機能を持たせ、チーム配布された設定の即時インポートと、各開発者が個別に編集可能な汎用サンプルの初期配置の双方を直感的に実行できるようにする。

1. **既存の config ファイルを指定して配置（インポート機能）**
2. **汎用性のあるサンプルの default config ファイルを配置し、各個人で編集する機能**

## 要求仕様一覧

- [x] 要求項目1: 既存 config ファイルの指定配置（インポート）機能
  - `devctl config init [source-path]` または `devctl config init --from <path>` により、指定された既存の YAML ファイルをユーザー設定パス（`~/.config/devctl/config.yaml`）へコピー・配置する。
  - 指定されたソースファイルの実在確認および YAML 構文バリデーションを配置前に実施し、不正なファイルの配置を防ぐ。
- [x] 要求項目2: 強制上書きフラグ（`--force` / `-f`）の追加
  - 配置先（`~/.config/devctl/config.yaml`）に既に設定ファイルが存在する場合、誤操作を防ぐため通常は警告を表示して処理をスキップする。
  - `--force`（`-f`）フラグが指定された場合は、確認または強制上書きを許可する。
- [x] 要求項目3: 汎用性のあるデフォルト設定テンプレート（`template.go`）の刷新
  - 引数未指定時に生成されるデフォルト設定（`DefaultConfigYAML`）を、特定個人のローカル環境に依存しない、汎用的で拡張しやすいサンプル構成へと刷新する。
  - 共通基盤（リバースプロキシ等）、共通ネットワーク、Web アプリケーション、API マイクロサービスなどの代表的構成例と、設定項目の日本語解説・プレースホルダーを含める。
- [x] 要求項目4: CLI ヘルプおよびメッセージの日本語化・UX 改善
  - `devctl config init --help` の説明文および使用例に、2つの機能（汎用サンプル生成 / 既存ファイル指定インポート）を明確に記載する。
  - ファイルコピー成功時、構文エラー時、未存在エラー時の案内メッセージを親切な日本語で出力する。
- [x] 要求項目5: 単体テストの追加と動作検証
  - 引数なしでのデフォルト生成、指定ファイルからのインポート、構文不正ファイルの拒否、`--force` フラグの動作を検証するテストコードを追加する。

## 変更対象の想定範囲

作業の影響を最小限に抑えるため、編集を想定するパッケージやファイルを明示する。

- 想定修正ディレクトリ/ファイル:
  - `internal/cmd/config_cmd.go` （`config init` の引数・フラグ処理、バリデーション、コピー処理）
  - `internal/config/template.go` （汎用サンプルテンプレートの刷新）
  - `internal/config/config.go` （設定ファイルの構文検証用ヘルパー関数の追加・調整）
  - `internal/cmd/config_cmd_test.go` または `internal/config/config_test.go` （単体テスト）
  - `README.md` （`devctl config init` の利用方法のドキュメント追記）

## 技術的制約および互換性

- 破壊的変更の許容: なし（引数なしで実行した場合の既存の基本動作を維持し、完全な後方互換性を担保する）。
- ランナー層の経由: 本機能はファイル操作・設定管理のため OS/Docker コマンド実行は伴わないが、既存の `--dry-run` 時のプレビュー表示等の安全性を考慮する。
- 外部パッケージの追加: 原則不可（Go 標準ライブラリおよび既存の Cobra / YAML パッケージの範囲内で実装すること）。
