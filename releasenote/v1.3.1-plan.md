## 変更の目的・背景

GitHub Issue #12（`共通基盤を docker compose up -d と devctl core up のどちらからでも起動できるか検証する`）への対応。
現行の共通基盤（`toolbox/compose.yml`）では `core-network` が `external: true` として定義されているため、事前に `devctl` でネットワークを作成していない初期状態で `toolbox` ディレクトリ直下から `docker compose up -d` を実行するとネットワーク未存在エラーで起動できない課題があった。
一方、`toolbox/compose.yml` 側で `external: true` を外して IPAM（Subnet / Gateway）付きのネットワーク定義を持たせた場合、そのままでは `devctl` の `NetworkManager.Create` が作成するネットワークに Docker Compose 管理ラベルが付与されないため、後から `docker compose up -d` を実行した際にラベル競合が発生する。
本改修では、`toolbox/compose.yml` に `core-network` のネットワーク定義（Subnet / Gateway / Attachable）を持たせるとともに、`devctl` 側でのネットワーク作成・共通基盤起動の互換性を担保することで、`devctl core up` と `toolbox` 直下での `docker compose up -d` の完全な相互運用・両立を実現する。

## 要求仕様一覧

- [x] 要求項目1: 共通基盤（`toolbox/compose.yml`）のネットワーク定義の自立化
  - `toolbox/compose.yml` の `networks.core-network` から `external: true` を外し、`name: core-network`、`driver: bridge`、`attachable: true`、および `ipam.config`（`subnet: ${SUBNET:-10.10.0.0/24}`, `gateway: ${GATEWAY_IP:-10.10.0.1}`）を明示定義する。
  - 各サービス（`traefik`, `dbgate`, `dozzle`）の `ipv4_address` も `.env` の環境変数（`${TRAEFIK_IP:-10.10.0.2}` 等）を参照するよう統一し、`toolbox` 直下の `docker compose up -d` 単体でネットワーク作成からサービス起動まで完結できるようにする。
- [x] 要求項目2: `devctl` のネットワーク管理と Docker Compose の相互互換性担保
  - `internal/docker/network.go`（または `core.go` / `project.go`）において、`devctl network create` や `devctl core up`、`devctl up <project>` で作成・確保されるネットワークと、`toolbox/compose.yml` で定義されたネットワークが競合しないようにする（Compose 互換ラベルの付与、または Core 起動時のネットワーク管理の整合性確保）。
  - `devctl core up` と `toolbox` 直下の `docker compose up -d` のどちらで先に起動しても、もう片方のコマンド（`devctl core ps/down/restart`、`docker compose ps/down`、および他プロジェクトからの `external: true` での接続）がエラーや警告なく動作することを保証する。
- [x] 要求項目3: 単体テストおよび実機での相互運用検証
  - `internal/docker/` または `internal/cmd/` の単体テストを更新・追加し、`go vet ./...` および `go test ./...` がエラー 0 件で通過することを確認する。
  - 以下のパターンを実機検証し、結果をリリースノート（`v1.3.1-released.md`）に記録する：
    1. ネットワーク未作成状態から `toolbox` 直下で `docker compose up -d` → `devctl core ps` / `devctl core down`
    2. ネットワーク未作成状態から `devctl core up` → `toolbox` 直下で `docker compose ps` / `docker compose down`
    3. 各起動方法におけるプロジェクト（`sample`）からの `core-network`（Traefik / DBGate）接続確認
- [x] 要求項目4: ドキュメントおよび設定例の同期更新（`documentation.md` 準拠）
  - `README.md` および `configs/config.example.yaml` に、共通基盤（Core）を `docker compose up -d` と `devctl core up` の双方から透過的に扱えるネットワーク設計ガイドを反映する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（既存の `config.yaml` や各プロジェクト側の `compose.yml` における `external: true` 参照の互換性を完全に維持すること）。
- **ランナー層の経由**: コマンド実行を変更する場合は必ず `internal/docker/runner.go` を経由し、`--dry-run` に対応させること。
- **外部パッケージの追加**: 原則不可（標準ライブラリおよび既存の Cobra / YAML パッケージの範囲で実装すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守し、`CGO_ENABLED=0` による静的リンク性を維持すること。
