## 変更の目的・背景

各プロジェクトにおけるマルチステージ Dockerfile（開発用/本番用ステージ分離）および Docker Compose の override 構成（`compose.override.yml` による開発環境上書き、`compose.prod.yml` による本番構成）に devctl をネイティブ対応させる。
従来の devctl では `-f compose.yml` のみが明示指定されていたため Docker Compose の標準挙動である `compose.override.yml` の自動読み込みがスキップされてしまい、本番用ステージ（`prod`）で誤ってビルドされたりバインドマウントが無効化される問題があった。
これを解決し、標準 override ファイルの自動認識・マージ機能、および CLI から本番ファイル等を重ねて指定できる `--file` / `-f` オプションを提供する。

## 要求仕様一覧

- [x] 要求項目1: Docker Compose override ファイルの自動認識・マージ
  - `internal/config/config.go`: 作業ディレクトリ内のベース Compose ファイル（`compose.yml` 等）とペアになる override ファイル（`compose.override.yml`, `compose.override.yaml`, `docker-compose.override.yml`, `docker-compose.override.yaml`）を自動検出し、ComposeFiles に反映可能とする。
  - `internal/docker/compose.go`: Compose コマンド引数構築時（`buildBaseArgs`）、override ファイルが存在していればベースファイルに続けて `-f <overrideファイル>` を自動で付加する（明示的な別ファイルや環境フラグ指定時を除く）。
- [x] 要求項目2: プロジェクト操作コマンドへの `--file` / `-f` フラグ追加
  - `internal/cmd/project.go`: `up`, `down`, `restart`, `logs` 等の各プロジェクトコマンドおよびトップレベル短縮コマンドに `--file` / `-f` フラグを追加。
  - 例: `devctl up sample -f compose.prod.yml` のように指定することで、開発用 override をバイパスして本番用 Compose ファイル等をベースファイルに重ねて適用可能とする。
- [x] 要求項目3: 単体テストの追加と既存機能の検証
  - override ファイル自動検出および引数組み立て（通常時 / `-f` フラグ指定時）の挙動を検証する単体テストを追加。
  - `go vet ./...` および `go test ./...` がすべて正常通過することを確認。
- [x] 要求項目4: 設定例とドキュメントの更新
  - `configs/config.example.yaml`: override 構成（開発用・本番用の分離）のベストプラクティスをコメント付きで解説。
  - `README.md`: Compose override 自動マージ仕様および `-f / --file` フラグによる環境切り替え操作を追記。

## 技術的制約および互換性

- 破壊的変更の許容: なし（既存の `config.yaml` や override ファイルを持たない通常プロジェクトとの完全な後方互換性を維持すること）。
- ランナー層の経由: コマンド実行は必ず `internal/docker/runner.go` を経由し、`--dry-run` 時にも自動マージされた `-f` 引数群が正確にプレビュー表示されること。
- 外部パッケージの追加: 不可（標準ライブラリおよび既存の Cobra / YAML パッケージの範囲で実装すること）。
- インデント規約: 半角スペース4文字を厳格に順守すること。
