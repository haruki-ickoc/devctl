## 変更概要

- GitHub Issue #14（`project / core に Docker volume の backup / restore コマンドを追加する`）への対応。
- 特定の `project` または `core`（共通基盤）の Compose 定義に属する Named Volume のみをスコープ限定で `.tar.gz` アーカイブに退避・復元できる `devctl project backup` / `devctl project restore` および `devctl core backup` / `devctl core restore` を追加。
- コンテナの強制削除を行わず、稼働中コンテナがある場合は実行を拒否して事前の `devctl stop <project>`（または `devctl core stop`）を必須とする安全設計を導入（あわせて `devctl core stop` / `devctl core start` も追加）。

## 破壊的変更（互換性への影響）

- なし（既存のサブコマンド体系や `config.yaml` の互換性を完全に維持しています）。

## 変更詳細

### 1. スコープ限定 Volume 解決・稼働チェック・退避/復元エンジン (`internal/docker/volume.go`)

- **`ResolveScopeVolumes` / `SelectTargetVolumes`**:
  - 対象スコープの Compose 定義（`-f` 指定および `BUILD_ENV` / 標準 override を含む）から論理 Volume 名と実 Docker Volume 名（`<compose-project>_<volume>` または明示 `name`）のマッピングを解決します。
  - スコープ外の Volume 名が指定された場合はエラーとして拒否し、無関係な Docker Volume やコンテナには一切影響しません。
- **コンテナ削除なしの整合性保護 (`VerifyVolumesNotInUse`)**:
  - 対象スコープに稼働中（`running`）のサービスが存在する場合、または対象 Volume をマウントして稼働中のコンテナが存在する場合は `backup` / `restore` の実行を拒否し、事前に `devctl stop <project>` / `devctl core stop` で一時停止するよう案内して非ゼロ終了ステータスを返します。
- **Backup / Restore とアーカイブ検証 (`BackupVolumes`, `RestoreVolumes`, `InspectBackupArchive`)**:
  - デフォルト保存先: `<対象WorkDir>/.devctl/backups/<project-or-core>-<YYYYMMDD-HHMMSS>.tar.gz`（`-o` / `--output` で変更可能）。
  - アーカイブ構造: トップレベルに `<論理Volume名>/` ディレクトリを配置する `.tar.gz` 形式。1つのアーカイブから特定 Volume のみを選択して復元可能です。
  - 復元前に Go 標準ライブラリ（`compress/gzip`, `archive/tar`）でアーカイブの破損・パストラバーサル・収録 Volume を検証し、上書き対象 Volume とアーカイブパスを表示した上で `[y/N]` 対話確認を行います（`-y` / `--yes` でスキップ可能）。
  - 復元先の実 Docker Volume が未作成の場合は、Compose 互換ラベル（`com.docker.compose.project`, `com.docker.compose.volume`）付きで自動作成します。

### 2. CLI サブコマンドの追加 (`internal/cmd/project.go`, `internal/cmd/core.go`)

- `devctl project backup [project-name] [volumes...] [-o/--output <path>] [-f/--file <compose-file>]`
- `devctl project restore [project-name] <backup> [volumes...] [-y/--yes] [-f/--file <compose-file>]`
- `devctl core backup [volumes...] [-o/--output <path>]`
- `devctl core restore <backup> [volumes...] [-y/--yes]`
- `devctl core stop [services...]` / `devctl core start [services...]`

### 3. 単体テストおよびドキュメントの更新 (`internal/docker/volume_test.go`, `internal/cmd/project_test.go`, `README.md`, `configs/config.example.yaml`)

- スコープ外 Volume 指定時の拒否、稼働中コンテナ存在時の拒否、アーカイブ検証（正常系・空ファイル・破損ファイル・パストラバーサル・未収録 Volume）、確認プロンプト制御、および `--dry-run` でのコマンド構築テストを追加。
- `README.md` および `configs/config.example.yaml` に使用方法・保存先・アーカイブ仕様を追記。
