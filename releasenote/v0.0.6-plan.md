## 変更の目的・背景

v0.0.5 で導入された固定 IP（Subnet / Gateway）設定機能を安全・確実に活用できるようにするため、既存 Docker ネットワークとの設定差異（Subnet / Gateway の不一致）を検知してユーザーに通知・警告する機能を追加する。また、各プロジェクトの `compose.yml` における固定 IP の具体的な設定例および検証手順を公式ドキュメント（`README.md`）に整備する。

## 要求仕様一覧

- [x] 要求項目1: `NetworkManager.InspectIPAM` メソッドの実装 (`internal/docker/network.go`)
  - 指定された Docker ネットワークの Subnet および Gateway を `docker network inspect` から取得するメソッドを追加する。
  - `--dry-run` フラグ時は適切にシミュレーション表示を行う。
- [x] 要求項目2: 既存ネットワーク担保時（`Ensure`）の不一致検知・警告処理
  - `NetworkManager.Ensure` において、対象ネットワークが既に存在する場合、`config.yaml` の `subnet` / `gateway` 設定と実環境の構成を比較する。
  - 不一致が検知された場合、警告メッセージ（設定差異の内容および `devctl network rm` による再作成の案内）を表示する。
- [x] 要求項目3: `devctl network check` コマンドの表示強化 (`internal/cmd/network.go`)
  - ネットワークの存在確認に加え、設定ファイルに `subnet` / `gateway` が定義されている場合は、既存ネットワークの Subnet / Gateway の一致確認結果を表示する。
- [x] 要求項目4: 固定 IP 設定ガイドおよび検証手順のドキュメント拡充 (`README.md`)
  - 各プロジェクト側の `compose.yml` での固定 IP 指定方法（`ipv4_address` と `external: true`）。
  - `devctl` による事前検証（`devctl network check`）や起動後の動作確認（`docker inspect`）、不一致時の対処法を分かりやすく記載する。

## 変更対象の想定範囲

- `internal/docker/network.go`
- `internal/cmd/network.go`
- `README.md`

## 技術的制約および互換性

- 破壊的変更の許容: なし（差異を検知しても警告の出力にとどめ、既存ネットワークを自動削除・強制変更するような破壊的処理は行わないこと）。
- ランナー層の経由: `docker network inspect` の実行は必ず `internal/docker/runner.go` を経由すること。
- `--dry-run` 対応: dry-run 実行時に意図しない実コマンド呼び出しを行わないこと。
- コーディング規約: インデントは半角スペース4文字とし、`go vet ./...` で静的解析警告が0件であること。
