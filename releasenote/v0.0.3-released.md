## 変更概要

- `devctl config init` を拡張し、チーム内で準備・配布された既存設定ファイルの指定インポート（`devctl config init [source-path]` / `--from`）に対応。
- インポート時に YAML 構文および `version` フィールドの事前検証（バリデーション）を行い、不正な設定の配置を防止。
- 既存の設定ファイルが存在する場合の安全な上書き制御フラグ（`--force` / `-f`）を追加。
- デフォルト生成される設定テンプレート（`template.go`）を、特定個人の環境依存値から汎用性のある代表的なサンプル構成（共通基盤、共通ネットワーク、Web / API プロジェクト構成、編集ガイド付き日本語コメント）へと刷新。
- `ValidateFile` 関数および `config init` の各動作パターンを検証する単体テストを追加。

## 破壊的変更（互換性への影響）

- なし（引数なしで実行した場合の既存の初期化動作および生成先パス `~/.config/devctl/config.yaml` は維持されており、完全な後方互換性を保っています）。

## 変更詳細

### 1. 既存設定ファイルの指定インポート機能

`devctl config init` にファイル引数（または `--from` フラグ）を指定することで、配布された設定ファイルを検証した上で `~/.config/devctl/config.yaml` にコピー配置できるようになりました。

```bash
# 引数で直接指定してインポート
devctl config init ./shared-config.yaml

# --from フラグで指定してインポート
devctl config init --from ./configs/team.yaml
```

- **配置前の事前バリデーション**:
  `internal/config/config.go` の `ValidateFile` 関数により、ファイルの存在確認および YAML 構文・devctl 必須フィールド（`version`）の正当性を確認した上で配置します。構文不正なファイルの場合は配置を安全に中断します。

### 2. 強制上書きフラグ (`--force` / `-f`)

既に `~/.config/devctl/config.yaml` が存在する場合、誤った上書きを防ぐために処理をスキップして案内メッセージを表示します。明示的に再配置したい場合は `--force`（または `-f`）を指定します。

```bash
# 既存ファイルが存在する場合でも強制上書きして再配置
devctl config init ./shared-config.yaml -f
devctl config init --force
```

### 3. 汎用的なデフォルト設定テンプレートの刷新

引数未指定時に生成される `DefaultConfigYAML`（[internal/config/template.go](file:///home/skyou/workspace/devctl/internal/config/template.go)）を、各開発者が自身の環境に合わせてスムーズに編集できるよう、汎用的な構成例へと見直しました。

- **共通ネットワーク**: `dev-network`
- **共通基盤 (Core)**: `~/workspace/core-infra` (Traefik, 共通DB, Redis)
- **プロジェクト例**:
  - `web-app`: フロントエンド・バックエンド構成 (DBマイグレーションやシード投入タスク例)
  - `api-service`: バックエンド API マイクロサービス (テスト実行タスク例)
- 各項目に親切な日本語コメントと編集ガイドラインを記載。
