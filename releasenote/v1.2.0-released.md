## 変更概要

- GitHub Issue #2（`projectのstart / stopを基本機能に追加してほしい`）に対応し、コンテナを破棄（削除）せずに一時停止する `devctl stop` と、停止済みコンテナを既存状態のまま高速再開する `devctl start` コマンドを新設しました。
- 特定のサービス（`services...`）のみを対象とした個別の開始・停止操作に対応しました。
- `-f / --file` フラグによるカスタム Compose ファイルの重ね合わせをサポートしました。
- コンテナ未作成時に `start` を実行してエラーとなった場合、初回起動用の `devctl up <project>` を案内する解決策ヒントを提示します。
- 単体テストの拡充、設定例およびドキュメントの同期更新を実施しました。

## 破壊的変更（互換性への影響）

- なし（既存の `up`, `down`, `restart`, `build` コマンドおよび `config.yaml` 構文との完全な後方互換性を維持しています）。

## 変更詳細

### 1. `internal/docker/compose.go` への `Start` / `Stop` メソッド追加

- `ComposeClient.Start(opts ComposeOptions) error` を実装。
- `ComposeClient.Stop(opts ComposeOptions) error` を実装。
- `c.runner.RunCommand` を経由し、`--dry-run` プレビューおよび終了ステータスの失敗伝播に完全対応。

### 2. `internal/cmd/project.go` へのコマンド新設

- `devctl project start [project-name] [services...] [flags]` および `devctl start` を新設。
- `devctl project stop [project-name] [services...] [flags]` および `devctl stop` を新設。
- `resolveTargetProject` によるプロジェクト名判定およびカレントディレクトリからの自動検出に対応。
- 引数でのサービス名個別指定および `-f / --file` フラグをサポート。
- `start` 失敗時のヒント表示（コンテナ未作成時は `devctl up` を推奨）。

### 3. 単体テスト・自動検証の拡充

- [internal/docker/compose_test.go](file:///home/skyou/workspace/devctl/internal/docker/compose_test.go):
  - `TestComposeClient_StartAndStop`: 通常実行時、サービス指定時、カスタム Compose ファイル指定時の引数組み立てと DryRun 実行を検証。
- [internal/cmd/project_test.go](file:///home/skyou/workspace/devctl/internal/cmd/project_test.go):
  - `TestStartStopCmd_FlagsAndRegistration`: `RootCmd` および `projectCmd` への登録、`-f / --file` フラグバインドを検証。
  - `TestStartStopCmd_Execution`: プロジェクト指定、サービス指定、存在しないプロジェクト時のエラーハンドリングを検証。

### 4. ドキュメントおよび設定例の更新

- [README.md](file:///home/skyou/workspace/devctl/README.md):
  - 「プロジェクト操作」セクションに `devctl start` / `devctl stop` の使用例を追加。
  - `up / down`（コンテナ新規作成・破棄）と `start / stop`（一時停止・高速再開）の使い分け解説ノートを追記。
- [configs/config.example.yaml](file:///home/skyou/workspace/devctl/configs/config.example.yaml):
  - ガイダンスコメントに `start` / `stop` を反映。
