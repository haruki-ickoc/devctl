## 変更概要

- GitHub Issue #3（`projectのbuildを基本機能として追加してほしい`）に対応し、コンテナを起動せずにイメージのビルドのみを実行する `devctl build` / `devctl project build` コマンドを新設しました。
- 特定のサービス（`services...`）のみを対象とした個別ビルドに対応しました。
- `--no-cache`、`--pull`、および `-f / --file`（別環境用 Compose ファイルの重ね合わせ）フラグをサポートしました。
- ビルド異常終了時のエラー（非ゼロ終了コード・エラーメッセージ）を確実に検知・伝播する失敗伝播の仕組みを担保しました。
- 単体テスト（`compose_test.go`, `project_test.go`）の拡充、設定例およびドキュメントの更新を実施しました。

## 破壊的変更（互換性への影響）

- なし（既存の `devctl up --build` や他のサブコマンド、`config.yaml` 構文との完全な後方互換性を維持しています）。

## 変更詳細

### 1. `internal/docker/compose.go` への `Build` メソッド追加

- `ComposeClient.Build(opts ComposeOptions, noCache, pull bool) error` を実装。
- 実行前に `--no-cache`, `--pull` フラグおよびサービス名リスト、追加引数を組み立てて `c.runner.RunCommand` を経由して `docker compose build` を実行。
- ランナー層経由により `--dry-run` プレビューに完全対応。
- プロセス終了ステータスをそのまま返却し、ビルドエラー時の失敗伝播を担保。

### 2. `internal/cmd/project.go` へのサブコマンドおよびトップレベルコマンド追加

- `devctl project build [project-name] [services...] [flags]` を新設。
- トップレベル短縮コマンド `devctl build [project-name] [services...] [flags]` を新設し `RootCmd` に登録。
- `resolveTargetProject` によるプロジェクト名引数およびカレントディレクトリからのプロジェクト自動検出に対応。
- フラグ定義:
  - `-f, --file`: 追加または上書き適用する Compose ファイル (例: `compose.prod.yml`)
  - `--no-cache`: キャッシュを使用せずに最初からイメージをビルド
  - `--pull`: 常に最新のベースイメージをプルしてビルド

### 3. 単体テスト・自動検証の拡充

- [internal/docker/compose_test.go](file:///home/skyou/workspace/devctl/internal/docker/compose_test.go):
  - `TestComposeClient_Build`: 通常実行およびフラグ（`no-cache`, `pull`, `-f`）やサービス指定時の引数組み立てと DryRun 実行を検証。
- [internal/cmd/project_test.go](file:///home/skyou/workspace/devctl/internal/cmd/project_test.go):
  - `TestBuildCmd_FlagsAndRegistration`: トップレベル `build` および `project build` の登録と各種フラグ（`--no-cache`, `--pull`, `-f`）のバインドを検証。
  - `TestBuildCmd_Execution`: プロジェクト指定、サービス指定、存在しないプロジェクト時のエラーハンドリングを検証。

### 4. 設定例およびドキュメントの更新

- [README.md](file:///home/skyou/workspace/devctl/README.md):
  - 「プロジェクト操作」セクションに `devctl build` の使用例（単体ビルド、サービス指定、`--no-cache`, `--pull`, `-f` 重ね合わせ）を追記。
- [configs/config.example.yaml](file:///home/skyou/workspace/devctl/configs/config.example.yaml):
  - コンテナビルドが第一級コマンドとして標準化されたため、`tasks` へのビルドコマンド登録が不要になった旨をガイダンス追記。
