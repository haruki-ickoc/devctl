## 変更の目的・背景

GitHub Issue #13（`project / core にイメージ取得用の pull コマンドを追加する`）への対応。
現行（v1.3.1）の `devctl` には、コンテナを起動せずに設定済みの Compose 定義からコンテナイメージのみを明示的に取得する標準コマンド（`pull`）が存在しない。
本改修では、`devctl project pull`（および短縮エイリアス `devctl pull`）と `devctl core pull` を新設し、各プロジェクトおよび共通基盤（Core）の設定（Compose ファイル、環境変数ファイル、作業ディレクトリ）に従って全サービスまたは指定サービスのイメージを事前取得できるようにする。

---

  - 最新の `develop` ブランチから機能開発用ブランチ `feature/pull-command` を新設して作業を行うこと。

## 要求仕様一覧

- [x] 要求項目1: `internal/docker/compose.go` への `Pull` メソッド追加および失敗伝播の実装
  - `ComposeClient.Pull(opts ComposeOptions) error` を追加する。
  - `buildBaseArgs(opts)` を用いて Compose ファイル（`-f` / `--file` 指定および自動 override マージを含む）と環境変数ファイル（`--env-file`）を構築し、ランナー層（`c.runner.RunCommand`）を経由して `docker compose ... pull [services...]` を実行する。
  - `--dry-run` 指定時は外部コマンドを実行せず、実行予定の Compose コマンド文字列を正確に出力する。
  - 認証情報は Docker 側の既存の認証設定（環境変数・`~/.docker/config.json`）をそのまま利用し、Compose の失敗時はエラーを呼び出し元へ確実に伝播させて非ゼロ終了ステータスを返す。
- [x] 要求項目2: `internal/cmd/project.go` への `pull` サブコマンドおよびトップレベル短縮コマンドの実装
  - `devctl project pull [project-name] [services...] [flags]` を新設する。
  - トップレベル短縮コマンド `devctl pull [project-name] [services...] [flags]` を新設し、`RootCmd` に登録する。
  - `resolveTargetProject` を用いて、プロジェクト名引数およびカレントディレクトリからのプロジェクト自動検出に対応する。
  - サービス名（`services...`）が指定された場合は、特定サービスのみを対象にイメージ取得を実行可能とする。
  - コンテナの起動・再作成および依存サービス自動起動（`prepareDependencies`）は行わず、イメージ取得のみを実行する。
  - `--file` / `-f` フラグ（追加または上書き適用する Compose ファイル）をサポートする。
- [x] 要求項目3: `internal/cmd/core.go` への `core pull` サブコマンドの実装
  - `devctl core pull [services...]` を新設し、`coreCmd` に登録する。
  - `cfg.Core.WorkDir` の設定検証およびディレクトリ存在確認（非 dry-run 時）を行い、`cfg.Core.ComposeFiles`・`cfg.Core.EnvFile` に従って全サービスまたは指定サービスのイメージを取得する。
  - コンテナの起動・再作成やネットワーク作成は行わず、イメージ取得のみを実行する。
- [x] 要求項目4: 単体テスト・自動検証の拡充
  - `internal/docker/compose_test.go` に `ComposeClient.Pull`（全サービス、サービス指定、`-f` 指定、`env_file` 指定時）の単体テストを追加する。
  - `internal/cmd/project_test.go` に `project pull` / `pull` / `core pull` のコマンド登録確認、Dry-Run 実行テスト、未登録プロジェクトや `core.workdir` 未設定時のエラー検証テストを追加する。
  - `go vet ./...` および `go test ./...` を実行し、静的解析警告・テスト失敗が 0 件であることを確認する。
- [x] 要求項目5: ドキュメントおよび設定例の更新（`documentation.md` 準拠）
  - `README.md` に `devctl pull` / `devctl project pull` / `devctl core pull` の概要と使用例（および `devctl build --pull` との使い分け補足）を追記する。
  - `configs/config.example.yaml` に `pull` コマンドに関する案内コメントを反映する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（既存の `devctl build --pull` や他のサブコマンド、`config.yaml` の互換性を完全に維持すること）。
- **ランナー層の経由**: 外部コマンドの実行は必ず `internal/docker/runner.go` を経由し、`--dry-run` 時には実行予定コマンドを正確に出力すること。
- **外部パッケージの追加**: 原則不可（標準ライブラリおよび既存の Cobra / YAML パッケージの範囲で実装すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守し、`CGO_ENABLED=0` による静的リンク性を維持すること。
