## 変更の目的・背景

初版（v0.0.1）で構築した devctl の基盤実装は、架空の構成（`core-infra`, `web-app` 等）および `docker-compose.yml` 固定のファイル名を前提としていた。
本バージョン（v0.0.2）では、実際のローカル開発環境に実在する共通基盤（`toolbox`）および各プロジェクト（`sample`, `catchUper`）の `compose.yml` 構造・ディレクトリ構成・ネットワーク（`internal-network`）に devctl を適合させ、設定ファイル仕様および Compose ファイル自動検出メカニズムを実運用に即した形へ刷新する。
あわせて、プロジェクト内の保守性および開発体験を日本語話者に最適化するため、ソースコード内の処理説明（コメント・docstring）や CLI のヘルプ・出力メッセージ、設定ファイル内の注釈について、日本語での記述に統一・刷新する。

## 要求仕様一覧

- [x] 要求項目1: Compose ファイル名の自動検出（Auto-discovery）
  - `core` や `projects` において `compose_files` が未指定の場合、対象の `workdir` 直下に存在する Compose 設定ファイルを優先順位（`compose.yaml` -> `compose.yml` -> `docker-compose.yaml` -> `docker-compose.yml`）に従って自動探索・設定する。
  - ファイルが存在しない場合は、後方互換性維持のためフォールバックとして `compose.yml`（または `docker-compose.yml`）を設定する。
- [x] 要求項目2: 設定ファイルサンプル（`configs/config.example.yaml`）の実在環境への適合
  - 共通基盤（Core）の構成を実在する `~/workspace/toolbox`（ネットワーク: `internal-network`、サービス: `traefik`, `dbgate`, `dozzle`）に更新する。
  - プロジェクト構成例を実在する `~/workspace/sample` および `~/workspace/catchUper`（`frontend`, `backend`, `scraper`）に更新する。
- [x] 要求項目3: 設定初期化テンプレート（`internal/config/template.go`）の更新
  - `devctl config init` で生成されるデフォルト設定テンプレートを、上記の実在環境（`toolbox`, `sample`, `catchUper`）に即した内容へと更新する。
- [x] 要求項目4: 共通ネットワーク設定のデフォルト値整合
  - デフォルトネットワーク名を `dev-network` から実環境で使用されている `internal-network` に更新し、`toolbox` のネットワーク構成と整合させる。
- [x] 要求項目5: 設定診断コマンド（`devctl config check`）による実在ファイルの検証
  - 実際のプロジェクト構造（`toolbox`, `sample`, `catchUper`）に対して `devctl config check` を実行し、パスおよび Compose ファイル（`compose.yml` 等）が正しく認識・検証されることを確認する。
- [x] 要求項目6: コード上の処理説明・コメントおよび CLI メッセージの日本語化
  - ソースコード（Go ファイル）内の構造体・関数・処理ブロックに対するコメントおよび docstring を日本語での記述に変更・統一する。
  - 各 Cobra サブコマンドの `Short` / `Long` 説明文、フラグの説明文、エラーメッセージおよび端末表示（UI 出力）を日本語話者向けに日本語で統一する。
  - 設定サンプル（`configs/config.example.yaml`）およびテンプレート（`internal/config/template.go`）内の注釈コメントを日本語で記述する。

## 変更対象の想定範囲

作業の影響を最小限に抑えるため、編集を想定するパッケージやファイルを明示する。

- 想定修正ディレクトリ/ファイル:
  - `cmd/devctl/main.go` （コメントの日本語化）
  - `internal/config/config.go` （Compose ファイルの自動検出処理、ネットワークデフォルト値の更新、コメント・メッセージの日本語化）
  - `internal/config/template.go` （`config init` 用テンプレートの実環境適合と日本語注釈化）
  - `configs/config.example.yaml` （実環境に即した設定サンプルへの刷新と日本語注釈化）
  - `internal/cmd/*.go` （Cobra コマンド説明・フラグ説明・出力メッセージ・コメントの日本語化、設定診断メッセージ調整）
  - `internal/docker/*.go` （Compose/Network/Runner の処理説明コメント・ログ出力メッセージの日本語化）
  - `internal/ui/*.go` （UI 出力装飾ユーティリティのコメント日本語化）

## 技術的制約および互換性

- 言語表記の統一: ソースコード内のコメント、CLI の標準出力・エラーメッセージ、ヘルプ文は自然な日本語表現で統一し、英語表記と日本語表記の混在を避けること。
- CLI コマンド体系の維持: コマンド名やフラグ名（英語体系のサブコマンド）は変更せず、説明文やメッセージのみを日本語化して既存の利用手順との互換性を維持すること。
- 破壊的変更の許容: なし（既存の `config.yaml` で明示的に `compose_files` やネットワーク名が指定されている場合はそれを最優先とし、完全な後方互換性を維持すること）。
- ランナー層の経由: コマンド実行を追加・変更する場合は必ず `internal/docker/runner.go` 等を経由し、`--dry-run` に対応させること。
- 外部パッケージの追加: 原則不可（Go 標準ライブラリおよび既存の Cobra / YAML パッケージの範囲内で実装すること）。
