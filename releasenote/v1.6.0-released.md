## 変更概要

- GitHub Issue #15（`.envのBUILD_ENVに応じたCompose overrideの自動適用をサポートする`）への対応。
- 対象プロジェクトの `.env`（または `env_file`）に定義された `BUILD_ENV`（例: `BUILD_ENV=local`）を読み取り、`--file` フラグを明示指定しなくても対応する Compose override（例: `_docker/compose.local.yaml` や `compose.local.yaml`）をベース Compose 定義と合わせて自動適用する機能を追加。
- `BUILD_ENV` が指定されている場合は異なる環境の override や開発用 `compose.override.yml` を誤適用しないよう保護しつつ、未設定時の従来動作および `--file` / `-f` 明示指定時の優先適用を維持。

## 破壊的変更（互換性への影響）

- なし（`BUILD_ENV` 未設定プロジェクトにおける既存の `compose.override.yml` 自動マージ、および `--file` / `-f` フラグ指定時の挙動は完全に維持されています）。

## 変更詳細

### 1. `.env` からの `BUILD_ENV` 読み取りロジック (`internal/docker/compose.go`)

- `resolveBuildEnv(workDir, envFile, baseFile string) string` および `parseBuildEnvFromContent` を追加しました。
- 以下の優先順位で `.env` ファイルを探索し、`BUILD_ENV` を読み取ります：
  1. `opts.EnvFile`（`config.yaml` の `env_file`）で指定されたファイル
  2. プロジェクト作業ディレクトリ直下の `.env`（`<WorkDir>/.env`）
  3. ベース Compose ファイルと同じディレクトリ内の `.env`（例: `<WorkDir>/_docker/.env`）
- コメント行（`#`）、`export` プレフィックス、クォート（`"..."` / `'...'`）、インラインコメントを適切に除外し、安全な環境識別子（`[a-zA-Z0-9_-]+`）のみを有効値として抽出します。

### 2. 環境別 Compose override の探索と `buildBaseArgs` への統合 (`internal/docker/compose.go`)

- `findEnvOverrideFile(workDir, baseFile, buildEnv string) string` を追加しました。
- ベース Compose ファイルと同じディレクトリ（例: `_docker/` またはプロジェクトルート）を最優先で探索し、ベースファイル名に合わせた環境別 override（`compose.<BUILD_ENV>.yaml` / `.yml`、`docker-compose.<BUILD_ENV>.yaml` / `.yml`）を検出します。
- `ComposeClient.buildBaseArgs(opts)` における Compose ファイル適用優先順位：
  1. **CLI で `--file` / `-f` 指定時**: 自動 override を除外し、ベースファイル + 指定ファイルを適用。
  2. **`.env` に `BUILD_ENV` 設定時**: ベースファイル + 対応する `compose.<BUILD_ENV>.*` を適用（対応ファイルが存在しない場合は他環境の override や `compose.override.*` を誤適用せずベースファイルのみ適用）。
  3. **`BUILD_ENV` 未設定時**: 従来通り標準の `compose.override.yml` / `.yaml` 自動マージを適用。

### 3. 単体テストおよびドキュメントの更新 (`internal/docker/compose_test.go`, `internal/cmd/project_test.go`, `README.md`, `configs/config.example.yaml`)

- `TestBuildBaseArgs` に以下のテストケースを追加：
  - `.env` の `BUILD_ENV=local` に応じて `_docker/compose.local.yaml` が自動適用されること
  - `BUILD_ENV` が異なる環境の override や標準 `compose.override.yml` を誤って適用しないこと
  - `BUILD_ENV` 設定時でも `--file` 指定時は指定ファイルが優先されること
  - `opts.EnvFile` に定義された `BUILD_ENV` も読み取れること
- `TestUpCmd_WithBuildEnvOverride` を `internal/cmd/project_test.go` に追加。
- `README.md` および `configs/config.example.yaml` に `BUILD_ENV` による自動 override 適用の説明を追記。
