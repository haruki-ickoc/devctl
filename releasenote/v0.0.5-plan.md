## 変更の目的・背景

1. 固定 IP（Static IP）環境の正式サポート:
   共通 Docker ネットワークにおいて Subnet および Gateway を設定可能にし、固定 IP アドレスを必要とするコンテナ構成をサポートする。
2. 既存バグの修正（Cobra のフラグ衝突による panic の解消）:
   ルートコマンドの短縮フラグ `-v` (`--verbose`) と、`down` サブコマンド（`devctl core down`, `devctl project down`, `devctl down`）の短縮フラグ `-v` (`--volumes`) が競合して panic が発生する不具合を解消する。

## 要求仕様一覧

- [x] 要求項目1: `internal/config/config.go` の `NetworkConfig` 構造体に `Subnet` と `Gateway` を追加
  - `Subnet string yaml:"subnet"` および `Gateway string yaml:"gateway"` を定義する。
  - YAML パースおよび単体テストが通ることを確認する。
- [x] 要求項目2: `internal/docker/network.go` の `NetworkManager.Create` および `Ensure` の引数・処理拡張
  - `subnet` と `gateway` を受け取り、指定されている場合は `docker network create` の実行引数に `--subnet <subnet>` および `--gateway <gateway>` を追加する。
- [x] 要求項目3: ネットワーク作成・担保処理の呼び出し元改修
  - `internal/cmd/network.go`: `networkCreateCmd` で `cfg.Network.Subnet` と `cfg.Network.Gateway` を渡す。
  - `internal/cmd/core.go`: `coreUpCmd` で `Ensure` 呼び出し時に `cfg.Network.Subnet` と `cfg.Network.Gateway` を渡す。
  - `internal/cmd/project.go`: `projectUpCmd` / `topUpCmd` で `Ensure` 呼び出し時に `cfg.Network.Subnet` と `cfg.Network.Gateway` を渡す。
- [x] 要求項目4: 設定ファイル例および初期化テンプレートの更新
  - `configs/config.example.yaml` および `internal/config/template.go` に `subnet` と `gateway` の設定例を追加する。
- [x] 要求項目5: `down` コマンドのフラグ衝突バグの修正
  - `internal/cmd/core.go` および `internal/cmd/project.go` において、`volumes` フラグの競合を解消する（`-v` の重複を排除し、大文字短縮 `-V` またはロングオプション `--volumes` のみに修正）。
  - `devctl core down -h`、`devctl project down -h`、`devctl down -h` が panic せずに正常終了することを確認する。

## 技術的制約および互換性

- 破壊的変更の許容: なし（既存の `config.yaml` で `subnet` や `gateway` が未指定の場合は従来通り引数なしでネットワークが作成されること）。
- フラグの変更: ルートの `-v` (`--verbose`) は維持し、`down` サブコマンド側の volumes フラグの重複を解消する。
- ランナー層の経由: コマンド実行は `internal/docker/runner.go` を経由し、`--dry-run` に対応させること。
- コーディング規約: インデントは半角スペース4文字を適用し、`go vet ./...` で警告が出ないこと。
