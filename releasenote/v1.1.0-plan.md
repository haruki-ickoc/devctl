## 変更の目的・背景

GitHub Issue #3（`projectのbuildを基本機能として追加してほしい`）への対応。
現行（v1.0.1）の `devctl` では、コンテナ起動と同時にイメージをビルドする `devctl up --build` はサポートされているが、**コンテナを起動（デタッチド起動）せずにイメージのビルドのみを実行する専用コマンド**が存在しない。
CI/CD 環境での事前ビルドや、ローカル開発時の特定サービス単体ビルド、環境別 Compose ファイル（`compose.prod.yml` 等）指定によるビルド検証を `devctl` 単一コマンドで完結できるようにし、サービスの個別指定、環境値・オプション指定、および失敗ステータスの確実な伝播を実現する。

---

## 開発・ブランチ運用方針

- **作業ブランチ**:
  - `develop` ブランチから機能開発用ブランチ `feature/build-command` を新設して作業を行うこと。
  - 実装および検証（`verify.sh`）完了後、リリースノート（`v1.1.0-released.md`）を作成し、`develop` へのマージ準備を整える。

## 要求仕様一覧

- [x] 要求項目1: `internal/docker/compose.go` への `Build` メソッド追加および失敗伝播の実装
  - `ComposeClient.Build(opts ComposeOptions, noCache, pull bool) error` を追加する。
  - ランナー層（`c.runner.RunCommand`）を経由して `docker compose build` を実行し、`--dry-run` に完全対応する。
  - ビルドプロセスが異常終了した場合（非ゼロ終了コードや Dockerfile エラー）、エラーを確実に呼び出し元へ伝播（ラップ）し、プロセスを非ゼロで終了させること（失敗伝播の担保）。
- [x] 要求項目2: `internal/cmd/project.go` への `build` サブコマンドおよびトップレベル短縮コマンドの実装
  - `devctl project build [project-name] [services...] [flags]` を新設する。
  - トップレベル短縮コマンド `devctl build [project-name] [services...] [flags]` を新設し、`RootCmd` に登録する。
  - `resolveTargetProject` を用いて、プロジェクト名引数およびカレントディレクトリからのプロジェクト自動検出に対応する。
  - サービス名（`services...`）が指定された場合は、特定サービスのみを対象にビルドを実行可能とする。
  - 以下のフラグをサポートする:
    - `--file` / `-f`: 追加または上書き適用する Compose ファイル（環境値・本番ステージ等）
    - `--no-cache`: キャッシュを使用せずに最初からイメージをビルド
    - `--pull`: 常に最新のベースイメージをプルしてビルド
- [x] 要求項目3: 単体テスト・自動検証の拡充
  - `internal/docker/compose_test.go` に `Build` メソッドの引数組み立てテストを追加（通常時、サービス指定時、`--no-cache`、`--pull`、`-f` 指定時など）。
  - `internal/cmd/` 配下に build コマンドのルーティングおよびフラグ受け渡し検証を追加。
  - `go vet ./...` および `go test ./...` を実行し、静的解析警告・テスト失敗が 0 件であることを確認する。
- [x] 要求項目4: ドキュメントおよび設定例の更新
  - `README.md` に `devctl build` コマンドの概要、主要フラグ、サービス個別指定の使用例を追記する。
  - `configs/config.example.yaml` に、自前タスク（`command: docker compose build`）の定義が不要になった旨のガイダンスを反映する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（既存の `devctl up --build` や他のサブコマンド、`config.yaml` の互換性を完全に維持すること）。
- **ランナー層の経由**: 外部コマンドの実行は必ず `internal/docker/runner.go` を経由し、`--dry-run` 時には実行予定コマンドを正確に出力すること。
- **外部パッケージの追加**: 原則不可（標準ライブラリおよび既存の Cobra パッケージの範囲で実装すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守し、CGO_ENABLED=0 による静的リンク性を維持すること。
