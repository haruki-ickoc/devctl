## 変更の目的・背景

GitHub Issue #15（`.envのBUILD_ENVに応じたCompose overrideの自動適用をサポートする`）への対応。
現行（v1.5.0）の `devctl` では、環境別の Compose override（例: `_docker/compose.local.yaml`）を適用する際に `devctl up <project> --file _docker/compose.local.yaml` のように毎回 `--file` で明示指定する必要があり、環境設定とコマンド指定が分離しているため指定漏れが起きやすい課題があった。
本改修では、対象プロジェクトの `.env` に定義された `BUILD_ENV`（例: `BUILD_ENV=local`）を自動で読み取り、対応する Compose override（例: `compose.local.yaml` / `_docker/compose.local.yaml`）をベース Compose 定義と合わせて自動適用できるようにする。

## 要求仕様一覧

- [x] 要求項目1: `.env` からの `BUILD_ENV` 読み取りロジックの実装 (`internal/docker/compose.go`)
  - 対象プロジェクトの作業ディレクトリ（`WorkDir`）を起点に、以下の優先順位で環境変数ファイルを探索して `BUILD_ENV` を読み取る `resolveBuildEnv(workDir, envFile, baseFile string) string` を実装する：
    1. `opts.EnvFile` で明示指定された環境変数ファイル
    2. プロジェクト作業ディレクトリ直下の `.env`（`<WorkDir>/.env`）
    3. ベース Compose ファイルと同じディレクトリ内の `.env`（例: `<WorkDir>/_docker/.env`）
  - コメント行（`#`）、`export` プレフィックス、クォート（`"..."` / `'...'`）、インラインコメントを適切に処理し、安全な識別子文字（`[a-zA-Z0-9_-]+`）のみを有効な `BUILD_ENV` 値として抽出する。
- [x] 要求項目2: `BUILD_ENV` に対応する Compose override ファイルの探索と `buildBaseArgs` への統合 (`internal/docker/compose.go`)
  - ベース Compose ファイルと同じディレクトリ（`filepath.Dir(baseFile)`、例: `_docker/` または `.`）内で、ベースファイル名に応じた環境別 override ファイル（`compose.<BUILD_ENV>.yaml` / `.yml`、`docker-compose.<BUILD_ENV>.yaml` / `.yml`）を探索する `findEnvOverrideFile(workDir, baseFile, buildEnv string) string` を実装する。
  - `buildBaseArgs(opts)` において以下の優先順位で Compose ファイルを適用する：
    1. CLI で `--file` / `-f`（`CustomComposeFiles`）が明示指定された場合: 自動 override を除外し、ベースファイル + 指定ファイルを適用する（従来の `--file` 指定を維持）。
    2. `.env` に `BUILD_ENV` が設定されている場合: ベースファイル（開発用 `compose.override.*` は除外）に、対応する `compose.<BUILD_ENV>.*` が存在すれば付加する。対応する override が存在しない場合は、異なる環境の override や `compose.override.*` を誤って適用せず、ベースファイルのみを適用する。
    3. `BUILD_ENV` が未設定の場合: 従来通り標準の `compose.override.yml` / `.yaml` 自動検出ロジックを適用する。
- [x] 要求項目3: 単体テスト・自動検証の拡充 (`internal/docker/compose_test.go`, `internal/cmd/project_test.go`)
  - `BUILD_ENV=local` 時に `compose.local.yaml`（および `_docker/compose.yaml` に対する `_docker/compose.local.yaml`）が自動適用されることのテストを追加する。
  - `BUILD_ENV` が異なる環境の override（例: `BUILD_ENV=stg` 時の `compose.local.yaml` や `compose.override.yml`）を誤って適用しないことのテストを追加する。
  - `BUILD_ENV` 未設定時の従来動作、および `--file` 指定時の優先動作が維持されることのテストを追加する。
  - `go vet ./...` および `go test ./...` を実行し、静的解析警告・テスト失敗が 0 件であることを確認する。
- [x] 要求項目4: ドキュメントおよび設定例の更新（`documentation.md` 準拠）
  - `README.md` および `configs/config.example.yaml` に、`.env` の `BUILD_ENV` による環境別 Compose override 自動適用の仕様・命名規則・使用例を追記する。

## 技術的制約および互換性

- **破壊的変更の許容**: なし（`BUILD_ENV` 未設定プロジェクトにおける既存の `compose.override.yml` 自動マージおよび `--file` / `-f` フラグの互換性を完全に維持すること）。
- **ランナー層の経由**: 外部コマンドの実行は必ず `internal/docker/runner.go` を経由し、`--dry-run` 時には実行予定コマンドを正確に出力すること。
- **外部パッケージの追加**: 原則不可（標準ライブラリおよび既存のパッケージの範囲で実装すること）。
- **コーディング規約**: インデントは半角スペース4文字を順守し、`CGO_ENABLED=0` による静的リンク性を維持すること。
